`effect-spacetimedb` is an Effect-first authoring layer for SpaceTimeDB modules.
You describe the module once, implement handlers with scoped Effect services,
then build native module exports and clients from the same contract.

This page goes from an empty directory to a reducer call on a server running on
your machine. The commands use Bun, which runs TypeScript directly; the install
step shows npm and pnpm too. Node.js must satisfy `^22.23.4 || ^24.22.1 || >=26.12.1`.

## Install the CLI

```sh
curl -sSf https://install.spacetimedb.com | sh
spacetime version install 2.16.1 --use
spacetime --version
```

Open a new terminal if `spacetime` is not found yet: the installer adds it to
your `PATH`. `spacetime --version` must report `2.16.1`. The CLI version must match the
`spacetimedb` package your project depends on, because `spacetime build` and
`spacetime generate` read a version-specific module format. If several versions
are installed, make sure the matching `spacetime` is the one on your `PATH`.

## Start a local server

In a terminal of its own:

```sh
spacetime start
```

It listens on port 3000 and keeps running. A fresh CLI's default server is
Maincloud, the hosted service, so the commands below all say `--server local`.

## Create the project

```sh
mkdir stdb-hello
cd stdb-hello
echo '{ "name": "stdb-hello", "private": true, "type": "module" }' > package.json
```

    "allowImportingTsExtensions": true,
    "noEmit": true,

  "include": ["src/**/*.ts"]

## Write the module

A module is three files, split for a reason: a client must not import the module
entry. The entry loads the host-only `spacetime:sys` modules, which exist only
inside the server, so importing it elsewhere fails with
`Cannot find package 'spacetime:sys@2.2'` on Bun and
`ERR_UNSUPPORTED_ESM_URL_SCHEME` on Node.

The contract declares the table and the callable functions. Everything else
imports it, and it imports nothing host-only.

```ts title="src/contract.ts"
import * as Stdb from "effect-spacetimedb"

export const message = Stdb.table("message", {
  public: true,
  columns: {
    id: Stdb.string().primaryKey(),
    text: Stdb.string(),
  },
})

export const MessageRow = Stdb.struct({
  id: Stdb.string(),
  text: Stdb.string(),
}).named("MessageRow")

export const MessageFunctions = Stdb.Group.make("Messages").add(
  Stdb.Fn.reducer("messageSend", {
    params: MessageRow,
  }),
  Stdb.Fn.procedure("messageList", {
    params: Stdb.struct({}),
    returns: Stdb.array(MessageRow),
  }),
)

export const QuickstartModule = Stdb.Module.make(
  "effect_spacetimedb_quickstart",
  {},
)
  .addTables(message)
  .add(MessageFunctions)
```

The implementation attaches a handler to each function. Handlers get what they
need by yielding services from the module.

```ts title="src/live.ts"
import * as Effect from "effect/Effect"
import * as Stdb from "effect-spacetimedb"
import { QuickstartModule } from "./contract.ts"

const { Db, Tx } = QuickstartModule

export const MessageFunctionsLive = Stdb.Builder.group(
  QuickstartModule,
  "Messages",
  {
    messageSend: Effect.fn(function* ({ id, text }) {
      const db = yield* Db
      yield* db.message.insert({ id, text })
    }),
    messageList: Effect.fn(function* () {
      const tx = yield* Tx
      return yield* tx.run(
        Effect.gen(function* () {
          const db = yield* Db
          return yield* db.message.toArray()
        }),
      )
    }),
  },
)
```

The entry compiles the module. Its only exports are `ModuleExports` and the
default schema: the SDK rejects any other named export, including an
`export *` of the contract, with `TypeError: exporting something that is not a
spacetime export`. A type-only re-export is erased and safe.

```ts title="src/index.ts"
import { build } from "effect-spacetimedb/server-compiler"
import { QuickstartModule } from "./contract.ts"
import { MessageFunctionsLive } from "./live.ts"

export type { QuickstartClientExample } from "./client.ts"

const compiled = build(QuickstartModule, [MessageFunctionsLive])

export const ModuleExports = compiled.exportGroup()

export default compiled.schema
```

A contract that declares Effect `HttpApi` routes, or anything else that loads
Effect's HTTP or encoding modules before `server-compiler` is imported, needs
`import "effect-spacetimedb/server-polyfills"` as the entry's first line.

## Publish it

From the project directory, build the module and publish it to the local server
under the database name `stdb-hello`. Database names are lowercase words joined
by dashes.

```sh
spacetime publish --server local --yes stdb-hello
```

## Call a reducer

The client imports only the contract. `Stdb.project` turns it into a typed
client with no generated code.

```ts title="src/client.ts"
import * as Stdb from "effect-spacetimedb"
import type * as StdbClient from "effect-spacetimedb/client"
import { QuickstartModule } from "./contract.ts"

const Quickstart = Stdb.project(QuickstartModule.spec)

/** Typechecked client calls shown in the package quick start. */
const clientExample = (
  http: StdbClient.ProjectedHttpClient<typeof QuickstartModule.spec>,
  session: StdbClient.WsSession<typeof QuickstartModule.spec>,
  messageId: string,
) => ({
  call: http.procedures.messageList({}),
  subscribe: session.subscribe(
    Quickstart.targets.tables.message.where((row) => row.id.eq(messageId)),
  ),
})

export type QuickstartClientExample = ReturnType<typeof clientExample>
```

Use a separate entry to run an HTTP call against the local database.

```ts title="src/send.ts"
import * as Effect from "effect/Effect"
import * as FetchHttpClient from "effect/http/FetchHttpClient"
import * as Stdb from "effect-spacetimedb"
import { QuickstartModule } from "./contract.ts"

const client = Stdb.project(QuickstartModule.spec).client.http.make({
  uri: "http://127.0.0.1:3000",
  databaseName: "stdb-hello",
})

const program = Effect.gen(function* () {
  yield* client.reducers.messageSend({ id: "first", text: "Hello" })
  yield* Effect.log(yield* client.procedures.messageList({}))
})

Effect.runPromise(program.pipe(Effect.provide(FetchHttpClient.layer)))
```

```sh
bun run src/send.ts
```

It logs the row it wrote. Typecheck the project with:

```sh
bunx tsc
```

The optional `token` in the client's config is a SpacetimeDB identity token.
Without one, the server treats each call as a new anonymous identity.

## Develop

`spacetime dev` rebuilds and republishes on every change, and keeps generated
client bindings in `src/module_bindings` up to date:

```sh
spacetime dev --server local --module-path . --server-only --yes stdb-hello
```

Run `spacetime generate` by hand for bindings without a dev loop. A WebSocket
session and its live subscriptions take them as its `DbConnection`; see
[Connection](/core-concepts/clients/connection).

```sh
spacetime generate --lang typescript --module-path . --out-dir src/module_bindings --yes
```

:::note

Plain `spacetime generate` is the default and its `DbConnection` can be passed
directly to the Effect client. Projects that do not want generated TypeScript in
their stricter type graph can use the published quarantined artifact pipeline
and a spec-typed facade described in [Codegen](/core-concepts/clients/codegen).

:::

## Patch the SDK

The patch fixes [client range comparisons for object-backed keys](https://github.com/clockworklabs/SpacetimeDB/pull/5970),
[host index classification for overlapping constraints](https://github.com/clockworklabs/SpacetimeDB/pull/5969)
and [branded primitive inputs to native builders](https://github.com/clockworklabs/SpacetimeDB/pull/6660)
in SDK 2.16.1.

Before relying on these SDK features, copy
[`patches/spacetimedb@2.16.1.patch`](https://github.com/miragegame/effect-spacetimedb/blob/v0.9.0/patches/spacetimedb@2.16.1.patch)
into your project. Its paths are relative to the `spacetimedb` package root, so
Bun applies it from your root `package.json`, and pnpm from the same entry
under `pnpm.patchedDependencies` or in `pnpm-workspace.yaml`:

```json
{
  "patchedDependencies": {
    "spacetimedb@2.16.1": "patches/spacetimedb@2.16.1.patch"
  }
}
```

Other package managers need their own patch mechanism. Apply it wherever the
SDK is installed, module and client packages alike.

## The same module in the native SDK

For comparison, the table and reducer above with no Effect layer. The params
accept any string, and the failure paths are yours to write.

```ts
import { schema, table, t } from "spacetimedb/server"

const spacetime = schema({
  message: table(
    { public: true },
    { id: t.string().primaryKey(), text: t.string() },
  ),
})

// The exported binding's name is the reducer name.
export const message_send = spacetime.reducer(
  { id: t.string(), text: t.string() },
  (ctx, { id, text }) => {
    ctx.db.message.insert({ id, text })
  },
)

export default spacetime
```
