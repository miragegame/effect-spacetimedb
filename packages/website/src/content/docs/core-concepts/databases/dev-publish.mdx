Build with the native SpacetimeDB CLI. The module entry imports the host-only
compiler and exports the compiled schema:

```typescript
import * as Stdb from "effect-spacetimedb"
import { build } from "effect-spacetimedb/server-compiler"

const Module = Stdb.Module.make("app")

const compiled = build(Module, [])
export const ModuleExports = compiled.exportGroup()
export default compiled.schema
```

`ModuleExports` and the default are the entry's only exports. The SDK refuses
any other named export with `TypeError: exporting something that is not a
spacetime export`, so a contract or a compiled value re-exported from the entry
stops both `publish` and `generate`. A type-only re-export is erased and safe.

Publish with the native CLI. `spacetime publish` builds the module first, or
takes a bundle you built yourself. The CLI's default server is Maincloud, so
name the server you mean:

```sh
spacetime publish --server local --yes <dbName>

spacetime build --module-path <moduleDir>
spacetime publish --js-path <moduleDir>/dist/bundle.js --server <url> <dbName>
```

Build, publish and generate bindings for the parent database. Its schema includes the mounted modules. A pinned canonical namespace lets you rename a TypeScript mount accessor without moving stored rows. If the canonical name changes, a data-preserving publish refuses to remove any old table that still contains rows. See [Submodules](/core-concepts/databases/submodules#names-and-migrations).

## Dev Loop

`spacetime dev` builds, publishes, and regenerates client bindings, and does it
again on every change. In a project whose module is the current directory:

```sh
spacetime dev --server local --module-path . --server-only --yes <dbName>
```

Without `--module-path` it looks for a `spacetimedb/` subdirectory, which is
where `spacetime init` puts a module. It works on an effect-spacetimedb module
as it does on any other. Its build typechecks, so a project without
`allowImportingTsExtensions` imports `./contract`, not `./contract.ts`
(`TS5097`). See the
[SpacetimeDB CLI docs](https://spacetimedb.com/docs/databases/developing) for its
other flags.

## Programmatic Dev Servers

`effect-spacetimedb/dev-server` is for tests and tools that need a temporary
local `spacetimedb-standalone` plus a published prebuilt bundle. It does not
build the module or generate clients, so build first. A relative `bundlePath` is
resolved against `cwd`, which defaults to `process.cwd()`.

The server needs a platform's file system, path and child-process services and an
HTTP client, and its scope owns the process:

```typescript
import * as NodeServices from "@effect/platform-node/NodeServices"
import * as Effect from "effect/Effect"
import * as Layer from "effect/Layer"
import * as FetchHttpClient from "effect/http/FetchHttpClient"
import { makeDevServer } from "effect-spacetimedb/dev-server"

const program = Effect.gen(function* () {
  const runtime = yield* makeDevServer({
    bundlePath: "dist/bundle.js",
    dbNamePrefix: "example",
  })

  yield* Effect.logInfo(
    `published ${runtime.databaseName} at ${runtime.baseUrl}`,
  )
})

const main = program.pipe(
  Effect.scoped,
  Effect.provide(Layer.merge(NodeServices.layer, FetchHttpClient.layer)),
)

await Effect.runPromise(main)
```

The runtime is its first database: `runtime.databaseIdentity`, `republish`,
`updateEnvironment`, `reset` and `remove` act on it. `runtime.publishDatabase`
publishes another bundle to the same standalone under a name you choose and
returns the same handle for it, which is how tests run
[inter-database calls](/core-concepts/functions/inter-database-calls): the host
delivers them only between databases on one standalone. For the same reason
every standalone the dev server starts has `localhost` added to its `NO_PROXY`
unless `standaloneEnvironment` sets `NO_PROXY` or `no_proxy` itself.
`publishEnvironmentOnly` is exported for tools that drive their own logged-in
CLI.

The generated server bundle must include
`effect-spacetimedb/server-compiler`; native `spacetime build` preserves its
side-effectful server polyfill import. To run handlers with no server at all, see
[Testing](/core-concepts/testing).

effect-spacetimedb controls the authored TypeScript contract and compiled
module exports; SpacetimeDB still controls local dev, publish, runtime storage,
and the generated client runtime. The optional
[quarantined codegen path](/core-concepts/clients/codegen) bundles native output
without replacing the native generator.
